# OMEGA-053/055/058/059/084/085 — offline orchestration boundary

**NOT PRODUCTION.** This module is an opt-in, deterministic, in-process fixture harness. It cannot authenticate the owner, run an MCP server/client over a network, provision separate sandbox processes, authorize external writes, or persist its run events. `SIMULATED_SUCCEEDED` is deliberately not a real task `SUCCEEDED` state. Nothing calls `omega_transition` or changes the API, model engine, GitHub App, identity or external accounts.

- OMEGA-053: existing `omega_mvi/db/migrations/001_tasks.up.sql` and `003_task_controls.up.sql`, `db/store.py`, and isolated `test_orchestration_db_contract.py` cover persisted ID/owner/trace/budget/permissions/deadline and append-only transition events. **Live proof still requires the sentinel-verified PostgreSQL CI job; this offline module has no durable orchestration event store.**
- OMEGA-055: `OfflineMcpFixtureRegistry` is only an MCP-*shaped* boundary contract. The four named tools require distinct fixed trust-domain tags and read scopes. Registry presence never supplies approval or a principal. **Tags are not OS/process/network isolation.** MCP transport, server identity, tool signing and least-privilege process sandboxes remain OPEN.
- OMEGA-058: outputs are strictly schema-checked with `synthetic://` references only; arbitrary content, nested data, URLs, new fields, exceptions and prompt-injection text never reach the next stage or event log. **Actual DLP/egress firewall across real tool processes remains OPEN.**
- OMEGA-059: max steps, failures, retries, simulated minor-unit cost, wall-clock duration, UTC deadline and cooperative cancellation are checked before dispatch and after return. **Blocking tool-process termination, atomic budget reservations and durable cancel flags remain OPEN.**
- OMEGA-084/085: plan → apply (not filesystem mutation) → test → audit runs entirely on synthetic callbacks. Retryable `test`/`audit` failure restarts bounded cycle. The "apply" label indicates a fixture stage, **not code execution or account write**.

Run from repository root: `python -m pytest -q omega_mvi/tests/test_orchestration_offline.py`. For authoritative PostgreSQL contract tests, only run `omega_mvi/tests/test_orchestration_db_contract.py` in the project's existing **disposable sentinel-verified** PostgreSQL test job; tests skip locally without this fixture and must not be interpreted as accepted.

Architecture integration prerequisites: trusted IdP and atomic signed approval ledger; audited read-only MCP client with per-server sandbox and egress control; server-maintained task state and outbox; persisted cancellation/retry/cost ledger; exact SHA CI/real database tests; independent review and owner acceptance. Do not wire this into the real runtime until those gates are met.
